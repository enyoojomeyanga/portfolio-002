# Phase 1 consolidated handoff

## Goals
- Preserve approved editorial placeholder shell and world routes.
- Keep private Studio inaccessible until authentication is implemented.
- Establish security-aware configuration and automated source checks.
- Configure official vinext Cloudflare compatibility layer *locally* on user's Ubuntu machine.
- Perform one integrated verification pass, then route smoke tests.

## Scope and evidence
- Actual pages and Next.js source were retained from the existing foundation.
- Cloudflare adapter cannot be bundled as tested/generated source because npm registry was inaccessible in the artifact environment. `npm run phase1:setup-cloudflare` uses the **official initializer** on the target machine, never deploys, and can be skipped when already initialized.
- No Supabase accounts, tables, buckets or deployments have been created.
- The public UI is a foundation shell, not a fully implemented approved design.

## Existing project update (recommended)
1. Back up or commit current source; `git status` should be clean if using git.
2. Download the **update ZIP** into `~/Downloads`, extract to a staging folder.
3. Copy **only** the updated `package.json`, `.gitignore`, `README.md`, scripts in `scripts/` and `docs/PHASE-1-COMPLETE.md` into the project. Never overwrite files generated by your prior `vinext init`.
4. If `npm install` has already run and vinext was already initialized, don't reinstall dependencies unnecessarily. Otherwise run `npm install` if package lock is outdated.
5. If vinext is missing: `npm run phase1:setup-cloudflare`. This runs `vinext check` then `vinext init --platform=cloudflare` and modifies dependencies/config only after deliberate execution.
6. `npm run phase1:verify`.
7. Start `npm run dev:vinext` (if initialized), then in another terminal `npm run test:routes -- http://localhost:3000` (use actual port). If not initialized, run `npm run dev` instead.

## Pass/fail gate
PASS only if:
- `phase1:verify` succeeds;
- adapter is present and Cloudflare build succeeds;
- all 6 routes pass HTTP smoke tests in vinext local runtime;
- /studio remains inaccessible and /api/health is public without secrets.

NOT PROVEN: production Cloudflare deployment, Cloudflare network behavior, Supabase integration, CMS security, performance or accessibility certification. All remain later milestones.

## Troubleshooting
- `npm: command not found`: install Node 22+ via nvm and check npm.
- `npx vinext` fails network: check network / DNS / npm registry, retry when available; don't delete working Next.js setup.
- `dev:vinext` missing: initializer not completed; use official `npx vinext init --platform=cloudflare` after reading errors.
- `typecheck` reports `cloudflare:*` types missing: initialize adapter and generate Cloudflare types according to installed vinext version; review generated tsconfig changes.
- Smoke test connection refused: server not running, wrong port, or startup failed.
- Smoke test `/studio` not 404: stop and inspect authorization boundary.
- Back out adapter safely: restore pre-init Git checkpoint or backup; do not blindly delete config files created by a successful initializer.

## No deployment in Phase 1
Do not run deploy commands until hosting/provider choice, privacy/content verification and production security gates have passed.
